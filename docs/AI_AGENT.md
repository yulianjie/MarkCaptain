# 写作 Agent

MarkText 内置一个 Rust 驱动的写作 Agent，默认提供 DeepSeek 预设。使用 Chat Completions 兼容协议，支持自定义服务地址、模型和本地 Ollama。模型需支持流式输出与工具调用。

## 为什么选择这个方案

| 方案 | 适用性 |
| --- | --- |
| **内置 Rust Agent + 兼容 API（采用）** | 复用现有 Tauri 后端，无须额外安装 Node/Python/CLI；文档上下文、工具权限、取消、审阅和撤销可直接融入编辑器。 |
| 外接 Codex / Claude CLI | 更适合整个代码仓库的任务；增加安装、登录和进程协议维护，通用文件操作也超出了写作助手当前需要。 |
| 前端直接访问模型 | 无法统一保护密钥，容易遇到跨域限制，也不利于管理取消和多窗口隔离。 |

使用应用自己维护的小型工具循环，避免额外引入完整 Agent 框架。DeepSeek 的[工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)描述了模型请求工具、应用执行、再把结果交还模型的流程。OpenAI 的[函数调用文档](https://developers.openai.com/api/docs/guides/function-calling)和 Ollama 的[兼容接口文档](https://docs.ollama.com/api/openai-compatibility)提供相应协议参考。

## 使用

1. 点击标题栏 **AI 助手**，或按 `Ctrl/Cmd+Shift+A`。也可在「视图」菜单或命令面板打开。
2. 点击面板齿轮进入「模型设置」。DeepSeek 预设使用 `https://api.deepseek.com` 和 `deepseek-flash`；模型名称可以按账号可用模型修改。OpenAI 地址预设为 `https://api.openai.com/v1`，Ollama 为 `http://localhost:11434/v1`，这两项需填写模型 ID。
3. 选择认证模式：需要 API Key 或自定义请求头的服务使用「系统凭据库认证」；无需认证的 Ollama 等本地服务选择「无认证本地服务」（Ollama 预设默认选择此模式）。无认证模式在读取、保存、测试连接及生成时均不访问系统凭据库，因此 Linux 没有 Secret Service 也可使用；不发送密钥或自定义请求头。切回认证模式后，之前保存在系统凭据库的凭据仍可使用，凭据库故障会明确报错，不会降级为明文保存。填好模型名称后点击「保存并测试」，本地服务需先运行并下载支持工具调用的模型。测试只发送一条测试消息。
4. 输入要求或选择润色、摘要、提纲、续写。输入框上方默认显示「当前文档 · 按需读取」。这表示允许按需访问当前快照；普通问答不会预先发送正文。在编辑器选中文字后，打开助手（包括 `Ctrl/Cmd+Shift+A`）或点击消息输入框，会自动附加选区。可展开预览核对文字、手动重新附加，或点击关闭按钮切回整篇文档；取消文档复选框后不会自动重新开启。源码和所见即所得模式都支持。
5. Agent 可查看文档提纲、搜索文字、按行读取相关段落，或一次提出最多 32 处互不重叠的 Markdown 替换。全文读取仅用于全文摘要、整体改写等任务。展开逐行差异对照（带原文行号）后，逐处应用/忽略，也可全部应用或忽略剩余修改。生成期间不会更改编辑器。
6. 应用后可以「撤回」，也可通过编辑器正常撤销操作恢复。应用与撤回会检查文档快照；同批已接受的修改不会阻止继续审阅其他项，手动编辑任何正文后则拒绝旧建议覆盖新内容。可逐处撤回，或撤回该批已应用的修改；全部应用只产生一次编辑器事务。应用后的内容遵循现有保存/自动保存设置。
7. 每项修改有稳定 ID，可填写最多 1000 字符的「审阅意见」。下一轮会逐项发送原文、建议、接受/拒绝/撤回/待审状态及意见，并要求模型保留已接受的内容、不重复提出已拒绝或撤回的修改。点击该项「按这个意见重写」可明确请求新的方案，其他已拒绝项仍保持拒绝；重写使用应用后的当前文档及原修改范围，新方案仍需审阅。输入框已有草稿或图片时请先处理草稿。启用本地历史后，ID、状态和意见会一同保存，旧历史会自动补齐稳定 ID；恢复的历史修改仍为只读。反馈也计入对话大小预算，超限会在发送前提示。

`Enter` 发送，`Shift+Enter` 换行。生成过程中可停止、切换文档或收起面板；每篇文档保留自己的对话。滚动查看旧消息时不会被强制拉回底部。窄窗口使用右侧浮层，面板支持键盘调整宽度，界面支持中文、英文、日文与内置主题。

### 使用回答和核对原文

- 完成的回答下展开「使用回答」，可直接插入光标位置、追加文末、替换选区或新建 Markdown 笔记，不会再次请求模型。插入操作保留原选中文字；替换选区需要非空选区。可先在编辑器重新定位或选择，再点击操作，也支持从编辑器用键盘切换到面板。
- 插入和替换会验证捕获位置的完整文档快照，正文发生变化时需重新选择，避免旧选区覆盖新内容。操作只作用于该回答所属文档；追加使用当前文档末尾。所有修改进入正常撤销和保存流程。新建笔记为独立的未保存标签，不覆盖原文。生成中、错误或停止后的不完整回答不能执行这些操作。
- 模型通过 `cite_document` 显式引用支持其结论的原文，面板显示「原文依据」卡片，标签为所支持的观点，悬停可查看引用全文。点击后在源码和所见即所得两种模式中定位并选中对应段落；支持多行和 Unicode。系统提示要求区分原文明示内容与模型推断，引用范围校验不等于核实模型解释是否正确。
- 引用使用附加快照的 1 起始行号，最多 200 行/48 KB；后端从快照生成真实原文，前端再次验证引用文本和范围，不将任意回答链接解释为原文位置。选区引用会换算成全文行号。文档改变后拒绝旧引用定位，需重新询问。修改审阅也提供「定位原文」，已应用部分修改后，旧快照位置同样受到保护。

### 全文参考与分章总结

- 默认附加选区时只提供选中文字。勾选「参考全文，仅修改选区」后，可读取全文作为背景，但修改建议仍限制在原选区；引用可定位全文。取消附加后不发送新的文档快照。Rust 独立验证选区的 UTF-16 边界（不接受半个代理对），并仅在该范围内匹配修改；前端继续使用原始编辑快照审阅和应用。
- 点击「分章总结」处理当前附加的文档或选区。系统按标题、行和代码围栏规划不重叠、无遗漏的分段，优先在章节边界拆分；超长行或代码块按 Unicode 码点继续分段。每段最多 24 KB，合并短章节避免大量微小请求；超过 2 MB 或 180 段时明确报错。
- 各段依次作为只读请求发送完整原文，再每四组笔记逐层汇总，最后生成全文摘要。中间笔记最多 6 KB，超限会保留已完成部分并提示重试；最终回答最多 80 KB。每个请求有独立的工具/超时预算，面板显示原文覆盖、已完成请求/总请求数和综合总结阶段，可展开查看已完成分段笔记。覆盖统计说明原文已送交模型，不等于验证模型没有遗漏观点。
- 停止或失败会保留已完成部分，「继续分章总结」只重试未完成请求。恢复前必须仍附加相同文档、范围及完整内容；正文变化后需新建总结。过程中切换标签不会混入另一篇文档。只有最终综合成功后才能使用「插入、追加、替换、新建笔记」；未完成的结果明确标示。默认进度保存在窗口内存中；启用本地历史后会保存已完成工作，重启恢复后可以继续。
- 分章总结主动发送所有分段正文，与普通问答的按需读取不同；它不包含图片或对话历史，且后端拒绝任何修改工具调用。模型仍可能概括失准，需核对分段笔记与原文依据。

### 手动附加多份参考文档

- 展开「参考文档」，选择已打开标签页或通过系统文件选择器添加 Markdown 文件。已打开文件优先捕获未保存的编辑缓冲区；Windows 路径大小写和分隔符差异不会绕过这一行为。列表显示文件名，可逐个移除。
- 每轮最多 8 份参考文档，单份最多 2 MB，总计 4 MB。参考文档为附加时捕获的只读快照；后续编辑原文件不会悄悄改变已附加或重试请求的内容，需要移除后重新附加。
- 模型初次只收到参考文档的名称、ID、行数和大小；通过 `documentId` 按需读取、搜索、引用。参考正文不会预先发送，没有工作区扫描。即使取消当前文档附加，也可读取手动附加的参考文档；当前文档仍是唯一允许修改的目标。
- 原文依据卡片显示文档名，点击后切换到正确标签并定位。未打开的文件需要与捕获内容完全相同才能重新打开定位；文件已改变则明确拒绝。没有磁盘路径的历史快照会打开独立未保存标签。选择文件期间切换或清空会话不会把迟到的结果附加到别处。
- 「分章总结」仍只处理当前附加文档或选区，不自动混入其他参考文档。

### 可选本地历史

- 点击面板顶部「历史对话」并勾选「在本地保存对话」，默认关闭。开启后会保存当前窗口已有对话以及后续内容；支持按标题搜索、恢复、删除和导出 Markdown。新建对话前保存旧对话，关闭窗口前取消生成并等待历史写入完成。
- 保存位置为应用配置目录下 `agent-history/`，每个会话一个 UUID JSON 文件。采用原子写入和版本检查，多个窗口不会覆盖彼此记录；删除留下不含正文的标记，拒绝迟到写入重新创建已删除内容。恢复会话以新的 UUID 继续，原归档保持可查。
- 存储最多 100 条对话、总计 128 MB，单条最多 16 MB。超过上限会显示错误，需自行导出并删除旧记录，不会自动丢弃历史。完整文档快照按内容及身份去重，引用只记录范围。
- 历史包含对话文字、引用、参考文档快照和分章总结的已完成工作；不保存图片，也不保存 API Key。恢复后会明确提示缺失图片，需重新附加后继续图片相关问题。模型看到的历史消息也标记图片已不可用。
- 恢复时只有路径/文档身份和完整正文匹配才复用已有标签，否则打开独立的未保存快照标签，绝不覆盖当前未保存修改。历史中的修改建议保留原状态和差异，但禁用应用与撤销；需要重新请求修改。分章总结重新校验任务图和结果大小，原文及选区一致时可继续未完成请求。
- 关闭本地保存前先写完当前记录，然后停止后续保存；已有记录仍可查看、导出和删除。历史不会广播给其他窗口或自动发给模型；继续聊天时才使用恢复后的消息。未配置的浏览器预览只使用内存，不访问真实磁盘历史。

### 图片输入

在消息输入框直接粘贴截图/图片，或点击「添加图片」选择 PNG、JPEG、WebP 文件。发送前可查看缩略图、点击放大、逐张移除；支持图片与文字一起发送，也支持只发送图片。普通文字粘贴仍使用输入框原来的行为。

- 每条消息最多 4 张图片，单张最多 5 MiB；整段对话最多 12 张、总计 20 MiB。超过限制会显示错误，不会悄悄丢弃图片。
- 图片随消息保留，用于后续追问和失败重试。未发送的图片、选区和文档附加开关按文档分别保存；异步读取图片期间切换文档不会把图片附加到另一篇文档。
- 图片仅在窗口内存保存，点击发送后由 Rust 通过兼容接口交给配置的服务。图片按 [OpenAI 官方图像输入协议](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)编码为 `text` / `image_url` 内容数组，使用内嵌 Base64 图片；纯文本消息保持原协议。不把图片上传至另一个图床。
- 模型必须同时支持图片输入、流式输出和工具调用。连接测试目前只验证文本请求；供应商拒绝图片请求时会明确提示检查视觉模型配置。应用不通过模型名称猜测视觉能力。

### 写作技能

点击面板顶部书本按钮打开「技能管理」。内置 **ELI5 通俗解释、Mermaid 图表、清晰简洁的写作、Markdown 说明文档、团队沟通文档、Markdown 协作写作** 六个技能，随原生程序内置，无须另外安装 CLI。团队沟通采用 Anthropic 官方 `internal-comms`；协作写作采用 MarkText 自主编写的精简 `markdown-coauthor`。

- 默认「技能 · 自动选择」：模型先看启用技能的名称和用途，需要时才通过工具读取正文、参考资料。
- 输入框上方可指定本次对话使用的技能；发送时只预加载明确指定的技能正文。
- 「导入 SKILL.md」从系统文件选择器导入整个技能文件夹中的文本资料；支持查看内容、启停和删除导入副本。技能配置保存在应用配置目录，重启后保留。
- 源码、固定版本、许可证和自定义技能格式详见 [AI_AGENT_SKILLS.md](AI_AGENT_SKILLS.md)。

## 数据和权限

- API Key 和自定义请求头内容保存到操作系统凭据库（Windows Credential Manager、macOS Keychain、Linux Secret Service），普通设置仅保存地址和模型。自定义请求头用于连接测试及每次 Chat Completions 请求；自定义 `Authorization` 优先于自动生成的 Bearer 密钥，`Host`、`Content-Length`、`Content-Type` 等由传输层控制的字段会被拒绝。Linux 需要可用且已解锁的 Secret Service。凭据库不可用时明确报错，不降级为明文存储。
- 密钥按规范化后的完整基础地址隔离；更换服务不会把旧服务的密钥发送给新地址。保存的密钥不会回传界面，留空保留，专用删除按钮可移除当前服务的密钥。
- 首次模型请求包含该文档的会话消息、附加文档的名称/行数/字节数以及启用技能的名称/用途。文档正文和未指定技能的正文按工具请求加载。聊天默认仅在窗口内存保留；可在历史面板启用本地持久化。未附加文档时模型仍会收到本次对话已有的消息。
- 工具白名单：`read_document`、`search_document`、`cite_document`、`propose_edit`、`read_skill`、`read_skill_file`。文档工具只能操作已附加的不可变快照；技能工具只能读取本轮启用技能包内的文本。无通用文件系统、Shell 或联网搜索工具。模型不能直接应用或保存修改。
- 修改在 Rust 和前端各验证一次，要求每处原文精确且唯一匹配、各处互不重叠，并限制在附加范围内。每批最多 32 处，总替换文本最多 240 KB；空原文用于在附加范围末尾追加，最多一处。文档 ID 和整篇内容快照必须仍匹配，才允许应用。
- 每窗口最多一个生成任务，最多 10 轮、每轮 8 个工具调用、每轮响应 2 MiB；整个任务最多 300 秒。聊天输入最多 240 KB，本地文档快照最多 2 MB，两者单独计量；每次发往模型的序列化消息最多 512 KB（图片数据按上述独立预算计量）。按行读取最多 200 行/48 KB，全文读取最多 240 KB，更长文档可分段读取。
- 取消会终止正在等待的网络请求；错误、截断或取消时不保留该轮未确认的修改。模型地址可使用 HTTP 或 HTTPS；HTTP 不加密请求内容和凭据，应仅用于受信任网络。应用不跟随重定向，也不把服务返回的原始错误或凭据写入日志/界面。
- AI 回复的 Markdown 经过 DOMPurify 白名单处理，不加载图片、脚本或其他远程资源。

## 代码与验证

- 后端：`src-tauri/src/commands/agent/`（配置/凭据、SSE 解析、工具执行、任务管理）。
- 前端：`src/stores/agent.ts`、`src/components/agent/`。IPC 由 `tauri-invoke.ts` 和 `tauri-bridge.ts` 管理。
- 单元测试覆盖选区范围、冲突保护、会话隔离、取消竞态和晚到事件。Rust 测试覆盖 UTF-8/SSE 分片、截断流、角色注入、权限边界及真实回环 HTTP 的多轮工具交互。
- 浏览器端到端测试使用模拟模型传输层，真实运行 Vue、Muya、CodeMirror、审阅、应用/撤回和撤销，以及设置、错误、停止、主题、窗口适配。
- 2026-09-13 验证：230 项前端单元测试、80 项 Rust 测试、30 项浏览器测试通过；前端构建和 ESLint 通过。独立应用标识的 Windows 调试构建在真实 WebView2 中通过原生 IPC、系统凭据保存/读取/删除、连接测试、多轮工具调用、修改审阅/应用/撤回和取消测试，模型服务为临时回环 HTTP 服务。测试凭据已删除，测试进程已退出。

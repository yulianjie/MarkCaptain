# M2 工作流：项目资料、文档检查与联网研究

M2 在 M1 的当前文档审阅与导出流程上增加可选的项目检索、项目写作规范、文档检查和联网研究。每项访问都单独授权；配置偏好不会授予文件或网络权限，也不会改变“建议先审阅、再由用户应用”的原则。

## 授权只读项目检索

1. 打开项目文件夹，在 AI 助手面板展开「项目资料」。项目必须是当前窗口已打开并由 Rust 工作区确认的目录。
2. 检查包含和排除的项目相对 glob，然后点击「允许搜索项目」。这会创建当前窗口、当前会话的只读 grant。修改包含/排除范围后，必须点击「更新范围并授权」；旧范围不会静默扩展。切换项目根目录会撤销旧 grant。
3. Agent 使用 `search_project` 做有预算的字面搜索，结果包含相对路径、标题、短片段和行号。搜索候选不等于读取全文；模型只在随后调用 `read_project_document` 时收到选中候选的行片段。项目文档永远是只读参考，不是修改目标。

检索不使用 embeddings 或语义向量索引。打开的未保存 Markdown 缓冲区优先于相同路径的磁盘版本，并在本次任务中冻结。前端把项目内有界未保存 Markdown 通过本地 IPC 交给 Rust，由 Rust 统一判断包含/排除 glob；只有授权范围内的内容能进入检索、读取和模型工具结果。花括号、字符类等有效规则不再由前端近似匹配。IPC 限额在范围过滤前计算，项目中其他过大的未保存缓冲区也可能要求先保存或关闭。

搜索会显示完整性状态。达到文件数、扫描量、步数、候选缓存预算，或有文件跳过/无法读取时，结果会标记为不完整，并提供原因。`complete: false` 不能解释为“其余文件中没有匹配”。

候选缓存已满时仍可筛选已有候选，不会重复占用缓存额度。只有成功读取过的来源可以引用；失败或重复读取不占新增来源名额。Rust 与界面共用 40 份成功读取来源的上限，第 41 份在返回正文前即被拒绝。

项目搜索自动排除 `.git`、`node_modules`、`target`、`build`、`dist`、`output`、`exports`、`cache`、`.markcaptain/cache` 等目录。导出预设声明的输出目录（包括自定义输出目录）也会自动排除，并参与 grant fingerprint；改动项目搜索配置或输出目录后，旧 grant 将需要重新授权。

## 项目写作规范

项目配置保存在项目根目录的 `.markcaptain/agent.json`，schema 版本为 1。读取缺失配置不会创建文件；保存时原子写入并校验旧 fingerprint，若文件已在其他位置变化，则要求重新加载后再保存。已知字段会补齐默认值，未识别扩展字段会保留。

保存前检查最终格式化 JSON 的 128 KiB 文件上限；超限时保留旧文件，避免写入后无法再加载。

```json
{
  "schemaVersion": 1,
  "writing": {
    "language": "zh-CN",
    "audience": "项目读者",
    "tone": "清楚、简洁",
    "glossary": [
      { "preferred": "MarkCaptain", "avoid": ["Mark Captain"] }
    ]
  },
  "projectSearch": {
    "enabledByDefault": false,
    "include": ["**/*.md"],
    "exclude": ["archive/**"]
  }
}
```

`enabledByDefault` 只影响界面是否建议启用项目搜索，不创建 grant。`writing` 规范也只有在本轮勾选「应用项目写作规范」后才随请求使用。项目配置不能保存 API key、认证头、密码、命令或程序路径；不应在其中放置任何凭据或权限 grant。

写入 fingerprint 覆盖配置文件内容及自动排除的导出输出目录。保存遇到 fingerprint 冲突时，不会覆盖另一处修改。删除或修改 `.markcaptain/agent.json` 也会使受其影响的项目搜索 grant 失效。

## 文档检查与模型检查

「本地文档检查」由 Rust 对当前 Markdown 缓冲区做确定性检查，不请求模型。它只检查：

- 标题级别是否跳级；
- 本地链接和图片目标是否存在，且目标位于当前文档或已授权项目范围内；
- 配置的术语表中，正文是否出现应避免的写法。

代码块和 YAML front matter 不参与术语匹配。外部网址不会被打开或核验；`#anchor` 是否存在、链接目标文档中的标题和语义也不会被检查。绝对路径、越界目标或没有可验证文件位置的链接不会被读取。受预算限制时结果显示不完整。

检查结果绑定发起时的文档身份和正文版本。编辑、切换标签或项目后，旧结果立即失效并提示重新检查；即使随后撤销或切回，旧的异步响应也不能重新显示为当前检查结果。

「请 Agent 只读检查」会把当前文档快照发送到所选模型，并另行标记 `readOnly: true`；模型返回带原文依据的矛盾、冗余、结构或解释不足等疑点。该模式不启用修改工具、项目 grant 或联网研究。

检查结果的「生成待审修订」会将当前 issue 和原文证据交给模型，请求一张新的修改审阅卡；它不是只把说明填入草稿。返回内容仍需逐项审阅，系统不会自动应用。

## 可选联网研究

联网研究默认关闭，每次请求都需要明确开启。关闭后该轮不带搜索/网页读取工具；发送请求后开关会自动关闭。

- 查询建议从当前文档标题和研究主题在本地生成。建议只是候选，不会自动联网；请先检查或编辑，再逐条批准确切查询词。只有完全匹配已批准词的 `search_web` 调用才会发送给 Bing。
- Bing 使用公开 RSS 搜索端点，不需要用户提供 Bing API key。搜索不可用时，可以自行填写公开文章 URL，再调用 `open_web_source` 读取；这不是自动把失败查询改写成网页地址。
- 直接 URL 只允许不带认证信息的 HTTP(S) 常用端口（HTTP 80、HTTPS 443）。主机名及每次重定向目标都会重新检查；只接受公网 DNS 地址，连接 peer 必须与 pin 的地址一致。请求不使用系统代理，最多跟随 4 次重定向；单次响应最多 1,500,000 bytes。
- 搜索每次最多返回 5 个结果；每任务最多 8 个批准查询、8 个直接 URL、24 个来源。打开网页正文只缓存在当前任务中，最多保留 18,000 个字符/来源；任务结束后运行时缓存消失。
- 可选「本次请求使用 Cloudflare 公共 DNS」默认关闭。开启后，Cloudflare 会收到用于解析的目标域名；不会收到 URL 路径、URL 查询参数或网页正文。该模式不修改系统 DNS，不使用代理；Cloudflare DoH 不可用时会明确失败，不会静默退回系统解析。参见 [Cloudflare DNS over HTTPS 文档](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/) 和 [Reqwest ClientBuilder 文档](https://docs.rs/reqwest/latest/reqwest/struct.ClientBuilder.html)。

## 可选审阅恢复与历史

本地 Agent 历史默认关闭。开启后才会保存会话任务、快照引用、修改补丁、审阅决定和状态，并沿用去重、大小上限、删除墓碑与 Markdown 导出。图片不保存；API key、项目 grant、包含/排除授权、联网开关、已批准查询词和项目写作权限不写入或恢复。

重启后恢复的审阅卡默认只读，不会应用待审修改。恢复会清除当前文档范围、手动参考附件和选区；项目 grant 与 Web 授权均回到关闭状态。历史 Web 来源卡只保留来源 ID、标题、URL、获取/发布时间和状态，不保存网页 excerpt；项目候选及其检索片段不会进入历史。曾实际读取的项目来源可作为本地只读审阅记录保留，但恢复时会移除原项目文件路径，不复活项目 grant。

如要重新审阅历史待审修改，必须显式点击「重新关联并校验待审修改」，并在系统文件选择器中选择一个 Markdown 文件。系统通过正常文件打开流程读取所选文档，以当前实际缓冲区与已接受修改形成的基线进行保守验证；只为可安全定位的待审项创建新的 pending 审阅卡。旧卡永久只读，已接受、忽略或撤回的决定不会重播，也不会自动应用新卡。外部改动、重复文本或其他歧义会保留只读历史并说明无法验证；用户可重新选择正确文件后再试。

关联期间暂停发送、重试及分章总结，文件读取返回后再次核验会话，避免活动请求失去接收目标。新卡保留经验证的原始请求关系，可在重新启用文档上下文后生成新建议；这不会修改归档快照、恢复项目或联网权限，也不会扩大原来的选区。

## 重要限制

下表是实现限制，用于解释截断和不完整状态；超限请求会报错或明确标记不完整，不代表剩余范围没有内容。

| 范围 | 当前上限 |
| --- | --- |
| 当前文档快照/单个项目 Markdown | 2,000,000 bytes |
| 同一请求的未保存项目缓冲区 | 128 个文件；每份 2,000,000 bytes；总计 16 MiB |
| 单个任务实际读取的项目来源 | 40 份；每份 2,000,000 bytes；总计 16 MiB。与手动附件分开计算 |
| 手动附加参考文档 | 8 份；每份 2,000,000 bytes；总计 4,000,000 bytes |
| 项目搜索 | 每任务最多 8 次；最多扫描 5,000 个 Markdown 文件、遍历 100,000 个目录项、扫描 128 MiB；最多缓存 50 个候选。预算或读取异常会返回 `complete: false` |
| 项目范围 glob | 最多 64 条包含规则、128 条排除规则；每条最多 256 bytes，必须为项目相对路径 |
| 确定性文档检查 | 文档最多 2,000,000 bytes；最多检查 128 个本地链接/图片目标，最多返回 200 条 issue |
| Web 研究 | 每任务 8 个批准查询词、8 个直接 URL、24 个来源；每个查询最多 5 个搜索结果；单次响应最多 1,500,000 bytes |
| 本地历史 | 最多 100 条 / 128,000,000 bytes；单条最多 16,000,000 bytes、512 个去重快照。项目读取快照与对话快照共同计入 |

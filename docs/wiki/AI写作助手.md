# AI 写作助手

[首页](https://github.com/yulianjie/MarkCaptain/wiki/Home) · [项目检索与联网研究](https://github.com/yulianjie/MarkCaptain/wiki/%E9%A1%B9%E7%9B%AE%E6%A3%80%E7%B4%A2%E4%B8%8E%E8%81%94%E7%BD%91%E7%A0%94%E7%A9%B6) · [同步与数据安全](https://github.com/yulianjie/MarkCaptain/wiki/%E5%90%8C%E6%AD%A5%E4%B8%8E%E6%95%B0%E6%8D%AE%E5%AE%89%E5%85%A8)

写作 Agent 用于理解资料、起草和修订 Markdown。模型提出建议，用户检查差异再应用。内置 Agent、只读项目资料、多文档修订和外部 MCP 分别有自己的授权范围。

## 配置与连接

从标题栏、右侧检查器、“视图”菜单、命令面板或 `Ctrl/Cmd+Shift+A` 打开 AI 助手，再进入助手设置。

1. 选择 DeepSeek、OpenAI 预设、自定义 OpenAI 兼容服务或本地 Ollama。
2. 填写基础地址与模型 ID，地址应按服务的兼容接口要求配置。
3. 选择系统凭据认证或不使用认证。无认证模式适合不要求密钥的本地服务，不携带已保存的认证材料。
4. 需要认证时填写 API Key 或自定义请求头；自定义 `Authorization` 优先于自动 Bearer Key。
5. 保存并测试连接，再用短消息、文档读取与修改建议分别验证所需能力。

密钥和认证头存于操作系统凭据库，按完整的规范化基础地址隔离。已保存的秘密不会回显；留空可保留，专用删除按钮用于移除。Linux 需要可用且已解锁的 Secret Service，失败时不回退到明文文件。HTTP 不加密提示词和凭据，应只用于受信任环境。

模型需支持流式 Chat Completions 和工具调用。图片任务还需视觉能力；连接测试只验证文本请求，不保证所有功能可用。模型服务、调用费用和本地模型部署由用户自行配置。

## 发起一次写作任务

选区菜单、编辑器右键、命令面板与助手中的写作操作提供润色、精简、续写、翻译、解释、术语和结构检查。选择操作会把指令填进草稿，检查后再发送。

可以直接输入：

```text
只润色选中的段落，保留事实、数字、链接和术语。
解释这段设计的前提，并引用原文依据。
比较附加的两份资料，列出不一致之处，不修改参考资料。
根据当前文档生成提纲，暂时不要修改正文。
```

面板显示本轮目标、选区、模型地址、参考来源与实际读取内容。发送前核对活动区域和附加范围。停止会取消正在等待的请求；失败可按提示重试，已完成的回答仍需自行核对。

## 当前文档、选区与参考资料

| 内容 | 作用与限制 |
| --- | --- |
| 对话消息 | 作为会话上下文；关闭文档附加不等于清空此前消息 |
| 当前文档 | 勾选附加后提供快照身份和元数据，模型按需读取正文 |
| 选区 | 用于限定阅读/修改范围；全文参考与可修改选区可以分开设置 |
| 手动参考文档 | 从已打开标签或文件选择器附加 Markdown，只读，可读取和引用 |
| 项目来源 | 需要另行授权搜索范围，始终只读，见项目检索专题 |
| 图片 | 发送后进入所配置模型的图片输入，不写入对话历史 |

普通请求先发送附加文档的名称、行数、大小及可用技能目录，未必立即发送全文。模型实际调用读取工具后，相应片段才进入后续请求。模型只读检查、分章总结等明确需要正文的流程会发送其对应快照或分段内容。

不要把“本地资料”理解为“离线模型”。配置远程地址时，实际使用的资料会离开本机。只附加准备交给该模型处理的内容。

手动参考最多 8 份，每份 2,000,000 UTF-8 字节，合计 4,000,000 字节。文档内容过大时可缩小选区或分段处理；预算不是模型一定能完成任务的保证。

## 回答、引用与分章总结

回答可复制、插入光标、追加文末、替换选区，或创建为新的未保存文档。插入类操作会改变缓冲区，应先核对目标和内容。来源引用可定位到授权原文；只读参考不能作为修改目标。

长文可使用分章总结，显示分段进度与已完成工作，支持停止后在原文/选区仍匹配的条件下继续。它按分段处理和汇总组织任务，并非一次向模型塞入无限全文。文档改变后需要重新校验；历史恢复的未完成总结也受原文一致性限制。

## 图片输入

可在消息框粘贴截图，或选择 PNG、JPEG、WebP。发送前可查看缩略图、放大和移除；支持文字加图片或只发图片。

- 每条最多 4 张，单张最多 5 MiB。
- 整段对话最多 12 张，总计 20 MiB。
- 图片随消息保留在窗口内存，用于追问与重试；恢复本地历史后需要重新附加。
- 发送时通过兼容接口直接交给配置的模型服务，不会另外上传图床。

编辑器正文的图片上传和 Agent 图片输入是两个功能，拥有不同的配置与数据路径。

## 审阅、应用与撤回

修改建议显示原始 Markdown 与差异，可定位原文、逐项应用、忽略并记录决定。差异视图细化中文变化、链接目标，并为表格、代码、Frontmatter 提供辅助查看；正文附近的预览是只读浮层，不进入保存和导出。

应用前检查快照身份、原文匹配、范围与冲突。重复原文需要明确定位，重叠或越界修改会被拒绝。文档后续发生变化时会重新校验；不能安全定位时，先重新比较并生成新的待审建议，不猜测替换位置。

应用、撤回和编辑器撤销/重做会同步审阅状态。后续手工编辑可能使原审阅无法再安全撤回，应以当前正文和冲突提示为准。

内置普通建议每批最多 32 处，总替换文本最多 240 KB。模型不会直接保存；用户应用后形成缓冲区修改，若普通自动保存已开启，仍可能按常规策略写盘。多文档修订另有暂停保存规则。

## 修订多个文档

1. 点击“修订多个文档”，勾选 1–8 个已打开标签，可包括有路径的未保存文档和未命名文档。
2. 可用“打开已有文档…”经正常文件选择器加入标签；打开文件不会立即发送请求。
3. 核对路径、模型与要求，再发送。每份快照最多 2,000,000 字节，合计 4,000,000 字节。
4. 逐文件查看差异，选择“应用此文档”“忽略此文档”或“撤回已应用修改”。
5. 到相应标签检查正文，使用正常手动保存写盘。

请求冻结所选集合；未勾选文档、只读参考及项目检索结果不会自动成为编辑目标。初始请求发送目标元数据，正文按工具读取；该入口默认不携带普通聊天的项目/Web 授权、参考正文或历史消息。

发送前暂停所选标签自动保存并等待在途保存结束；不更改全局偏好。每篇最多一份建议、32 处互不重叠替换。没有跨文件“全部应用”或全局撤销事务，每篇保留各自正常撤销历史；某篇冲突不必阻止其他有效文档的审阅。

应用/撤回还检查磁盘原始字节、路径、标签身份及缓冲区。外部编辑、删除、改名、关闭重开，或等待期间的保存和目标变化会使旧操作失效。手动保存改变基线后，旧建议也可能要求重新请求。

“查看原文副本”展示本次任务起始快照，“转到文档”定位原标签。原文副本、读取记录和多文档审阅只留在当前应用会话；新请求替换旧任务，退出后不恢复，不进入普通对话历史。停止或生成期间关闭对话框会取消任务，已经收到并通过校验的建议可保留人工审阅。

## 写作技能

助手顶部书本按钮打开“技能管理”。内置六个技能：

| 技能 | 用途 |
| --- | --- |
| 通俗解释 · ELI5 | 简化复杂概念，保持事实准确 |
| Mermaid 图表 | 用支持的 Mermaid 语法组织图表 |
| 清晰简洁的写作 | 提高文字清晰度，减少冗余 |
| Markdown 说明文档 | 起草项目与使用说明 |
| 团队沟通文档 | 进展、计划、FAQ 等沟通材料 |
| Markdown 协作写作 | 按读者和目标起草、修订与检查 |

默认由模型按名称和用途自动选择，正文按需读取；也可在输入框上方明确指定。可导入本地 `SKILL.md`，查看、启停或删除导入副本；移动原始目录不影响已导入内容，更新时重新导入。

技能入口需要 YAML `name`、`description` 与正文。导入的是允许格式的文本资料，不运行脚本，不赋予额外工具或文件权限。导入文本可能发送给模型，需按自己的资料用途选择。完整格式、限额和许可见[技能说明](https://github.com/yulianjie/MarkCaptain/blob/master/docs/AI_AGENT_SKILLS.md)。

## 可选本地对话历史

对话历史默认关闭，在历史面板中启用。开启后可保存任务、消息、快照、审阅状态和已完成的总结，支持查看、Markdown 导出与删除；不保存图片、API Key 或运行时权限。

恢复历史时不会覆盖当前未保存修改；必要时打开独立快照。历史审阅卡默认只读，不能直接应用或撤回。需要重新审阅时，显式选择“重新关联并校验待审修改”，通过文件选择器选择 Markdown，由当前正文验证后生成新的待审卡；旧卡和既有决定不会重播。

恢复会清空当前附加范围、选区、手动参考和项目/Web 授权。不能验证、有歧义或外部变化时保留只读历史，要求重新处理。历史上限为 100 条/128,000,000 字节，单条上限 16,000,000 字节；它不等于文档本地版本历史。

## 外部 Agent：MCP 文档接入

在“External Agent (MCP)”中授权当前文档，可让可信本地 MCP 客户端读取一份编辑器缓冲区，包括未保存内容及选区信息。这里授权的是整篇文档，选区只是元数据，不是缩小的读取权限。

1. 保持该文档和 Agent 面板打开，点击授权。
2. 使用面板显示的 `node "<adapter path>"` 命令作为客户端的 stdio MCP server，需要 Node.js 18+。
3. 显示临时凭据，用客户端临时环境注入 `MARKCAPTAIN_MCP_PORT` 与 `MARKCAPTAIN_MCP_TOKEN`。
4. 外部客户端读取文档、提交建议，用户在 MarkCaptain 内审阅；客户端可查询审阅结果。

临时 Token 不应放入 URL、命令参数、Shell 历史、项目配置或 Git。持有 Token 的本地进程可使用该授权。切换文档、关闭文档/面板/窗口、撤销授权或租约失效都会使授权停止，重新授权产生新凭据。

桥接仅提供读取、待审建议与结果查询，没有其他路径读取、直接应用、保存、网络或 Shell 工具。它不限制外部客户端自身已有的其他权限。接入协议和示例见[外部 Agent 文档](https://github.com/yulianjie/MarkCaptain/blob/master/docs/EXTERNAL_AGENT.md)。

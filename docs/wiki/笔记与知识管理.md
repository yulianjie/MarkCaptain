# 笔记与知识管理

[首页](https://github.com/yulianjie/MarkCaptain/wiki/Home) · [编辑与工作区](https://github.com/yulianjie/MarkCaptain/wiki/%E7%BC%96%E8%BE%91%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8C%BA) · [同步与数据安全](https://github.com/yulianjie/MarkCaptain/wiki/%E5%90%8C%E6%AD%A5%E4%B8%8E%E6%95%B0%E6%8D%AE%E5%AE%89%E5%85%A8)

笔记功能以当前打开的项目目录为范围，继续使用普通 Markdown。打开文件夹后使用左侧笔记面板，或从命令面板寻找操作。笔记索引不会给 Agent 增加读取权限。

## 快速打开与创建

按 `Ctrl/Cmd+K`，输入文件名、相对路径或 YAML 别名，方向键选择、Enter 打开。空查询显示最近笔记，已有标签会复用。结果包含相对路径，用于区分同名文件。

无精确匹配时，可使用“创建”建立 `.md` 文件；不会覆盖已有文件。大型项目中搜索结果受预算和显示数量限制，应留意索引状态。

## 模板与每日笔记

项目笔记设置保存在 `.markcaptain/notes.json`。通过“笔记项目设置”管理目录与模板，默认模板目录是 `Templates`、每日笔记目录是 `Daily`、日期格式是 `YYYY-MM-DD`。

使用“插入文档模板”或 `Ctrl/Cmd+Alt+T`，可选择项目模板，或会议记录、读书笔记、工作日志示例。模板插入当前活动区域的光标位置，可以撤销。

支持以下变量，日期格式使用 `YYYY`、`MM`、`DD`、`HH`、`mm` 等常见写法：

| 变量 | 用途 |
| --- | --- |
| <code>&#123;&#123;title&#125;&#125;</code> | 标题 |
| <code>&#123;&#123;date&#125;&#125;</code> | 日期 |
| <code>&#123;&#123;time&#125;&#125;</code> | 时间 |
| <code>&#123;&#123;date:YYYY/MM/DD&#125;&#125;</code> | 自定义日期格式 |

示例模板：

<pre><code># &#123;&#123;title&#125;&#125;

日期：&#123;&#123;date&#125;&#125; &#123;&#123;time&#125;&#125;

## 记录

## 后续任务

- [ ] 整理结论
</code></pre>

“今日笔记”或 `Ctrl/Cmd+Alt+D` 会打开当天文件；不存在时使用指定模板创建，已存在时保留已有正文及未保存缓冲区，不重复覆盖。模板和每日笔记目录必须位于项目内。

文档模板决定正文结构，Agent 的 `SKILL.md` 决定模型写作指令，两者分别管理。

## 内部链接与别名

| 写法 | 含义 |
| --- | --- |
| `[[项目计划]]` | 按笔记名称引用 |
| `[[项目/计划]]` | 按项目内路径消除同名歧义 |
| `[[项目计划\|计划说明]]` | 保留自定义显示文字 |
| `[[项目计划#里程碑]]` | 链接到目标标题 |
| `[[#当前标题]]` | 当前文档内跳转 |
| `[项目计划](项目计划.md)` | 标准 Markdown 相对链接 |
| `[安装](../指南/安装.md#环境准备)` | 相对上级目录和标题 |

源码和可视化编辑器均提供 `[[` 补全。按住 `Ctrl/Cmd` 点击可跳转，也可从链接列表或链接浮层使用跳转入口。普通点击仍可编辑链接。

标准 Markdown 链接按源文件目录解析，支持 `../`、中文与空格、URL 编码、引用式链接和标题锚点。单独打开文件（未打开项目）时也能跳转；目标文档已打开时复用现有标签页，目标不存在时在编辑器内提示错误并保留当前文档。`[章节](#标题)` 在当前文件内滚动到对应标题，支持中文标题。网页链接由系统浏览器打开。

项目内 Wiki 短名称优先匹配引用文件所在目录，仍有歧义时使用完整路径。别名来自 YAML 的 `aliases` 字符串或字符串列表，例如：

```yaml
---
aliases:
  - 发布方案
  - 发版计划
tags:
  - work/release
priority: 2
done: false
date: 2026-10-24
---
```

Markdown 内链可省略 `.md` 指向已有笔记；项目内不存在的无扩展名目标可经创建提示建立 `.md`。带 PDF 等其他扩展名的目标不会被当成 Markdown 笔记创建。

## 反向链接与未链接提及

右侧检查器“双链”显示当前文档链接、反向链接和未链接提及。可筛选、按来源展开上下文、固定目标，在当前或另一分屏定位，并返回原位置。固定双链区域后可以同时查看 Agent。

反向链接表示其他笔记明确引用了目标；未链接提及表示正文出现了名称但尚未建立链接。分析排除代码和已经链接的文字，有歧义的名称不会任意分配给某篇笔记。

已有路径的未保存缓冲区会参与关系分析；未命名文档没有稳定项目身份。正在索引、索引不完整和没有关系是不同状态，不完整结果不代表其余文件没有引用。

## 重命名、移动与引用维护

在项目文件树中重命名或剪切移动笔记时，先查看将受影响的引用及歧义提示。应用会保留显式显示文字、标题锚点，并在移动源文档时重算其 Markdown 相对路径。

推荐步骤：

1. 保存或关闭项目中有未保存修改的相关标签，解决外部冲突。
2. 发起重命名/移动，查看引用更新预览。
3. 确认后，应用会暂停相关编辑并再次核对文件。
4. 文件在预览后发生增删或内容变化时，需重新预览，不会直接覆盖。
5. 完成后检查新路径、链接与打开的标签。

写入失败会自动回滚。命令面板“恢复上次引用更新事务”可撤回最近一次引用更新：它会再次检查版本，拒绝覆盖后续改动；成功后同步更新打开的文档。备份位置见[同步与数据安全](https://github.com/yulianjie/MarkCaptain/wiki/%E5%90%8C%E6%AD%A5%E4%B8%8E%E6%95%B0%E6%8D%AE%E5%AE%89%E5%85%A8#%E9%85%8D%E7%BD%AE%E4%B8%8E%E6%95%B0%E6%8D%AE%E4%BD%8D%E7%BD%AE)。

外部程序重命名或移动文件会使索引更新，但不会自动改写引用。

## 标签与属性

笔记面板可切换链接、标签、属性、结构化搜索与任务。

标签合并正文 `#标签` 和 YAML `tags`。`work/team` 同时归入父级 `work`，同一文档只计一次；点击标签可筛选相关笔记。

属性编辑支持文本、字符串列表、数字、布尔和日期。它只替换选定 YAML 值或添加字段，尽量保留其他内容、注释和未知数据；相同值不重写格式。改动进入正常撤销与保存流程。

嵌套对象、自定义标签、YAML 锚点、多行文本及复杂列表应在源码中编辑。无效 YAML 会拒绝修改，避免把无法理解的头部直接重写。

## 结构化搜索

可用字段：

| 字段 | 示例 | 作用 |
| --- | --- | --- |
| `name:` | `name:"Weekly sync"` | 名称或别名 |
| `path:` | `path:会议` | 相对路径 |
| `tag:` | `tag:work` | 标签，包含子标签 |
| `prop.属性名:` | `prop.priority:>=2` | 属性相等或数字比较 |
| `task:` | `task:open`、`task:done`、`task:any` | 任务状态 |
| 普通词 | `发布` | 代码之外的正文 |

示例：

```text
name:"Weekly sync" path:会议
tag:work prop.priority:>=2 NOT task:done
tag:reading OR tag:research
-tag:archive task:open
```

空格或 `AND` 表示同时满足；`OR` 或独立的 `|` 表示条件组之间任一满足；`NOT` 或字段前的 `-` 排除。AND 优先于 OR，当前不支持括号。含空格的值需要双引号；无效语法会显示错误。

需要全文或正则搜索时，使用原有“搜索”面板。它与结构化搜索入口和范围规则不同。

## 任务汇总

任务面板汇总项目中**未完成**的 Markdown 任务，排除代码示例。点击任务文字定位，勾选会通过活动编辑器把 `[ ]` 改为 `[x]`，可以撤销；完成后该任务从列表移出。写盘仍使用普通保存或自动保存。查找已完成任务可用结构化搜索 `task:done`。

任务和结构化结果最多显示 1000 条。任务面板不提供提醒、日历同步或后台通知。

## 索引范围与不完整结果

索引只扫描当前项目，跳过符号链接以及 `.git`、`.markcaptain`、`node_modules`、`target` 等目录；导出配置中的输出目录也被排除。已打开项目文档的未保存正文覆盖磁盘版本参与索引，文件监视触发增量更新，可重建索引。

单文件索引正文上限 4 MiB，项目正文总上限 128 MiB。无法读取、解码失败或超限会标记不完整，并阻止需要完整依据的引用改写。超大笔记可以继续普通编辑，但双链、任务和引用分析不会覆盖其全文。

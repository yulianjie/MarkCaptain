# 项目检索、文档检查与联网研究

[首页](https://github.com/yulianjie/MarkCaptain/wiki/Home) · [AI 写作助手](https://github.com/yulianjie/MarkCaptain/wiki/AI%E5%86%99%E4%BD%9C%E5%8A%A9%E6%89%8B) · [导出与成册](https://github.com/yulianjie/MarkCaptain/wiki/%E5%AF%BC%E5%87%BA%E4%B8%8E%E6%88%90%E5%86%8C)

本页介绍内置 Agent 的可选资料能力。打开项目、保存偏好或恢复历史都不会自动获得读取或联网权限。

## 授权项目资料

1. 打开本地项目，在 AI 助手中展开“项目资料”。
2. 核对包含/排除的项目相对 glob，例如包含 `**/*.md`、排除 `archive/**`。
3. 点击“允许搜索项目”，建立当前窗口和会话的只读授权。
4. 请求 Agent 查找资料；查看候选、实际读取记录和引用。
5. 调整规则后点击“更新范围并授权”；切换项目或相关配置变化时重新授权。

检索做有预算的字面匹配，不使用 embeddings。搜索返回路径、标题、短片段和行号；模型需要进一步调用读取工具才能获取选中候选的正文片段。只有成功读取的来源可以引用，资料始终只读。

项目内已打开且未保存的 Markdown 在任务中冻结，并优先于磁盘版本。未保存缓冲区的 IPC 总预算在范围过滤前计算，项目中其他过大的未保存标签也可能要求先保存或关闭。

默认排除 Git、依赖、构建、缓存和输出目录；项目导出配置声明的自定义输出目录也会排除。路径及授权由后端检查，不通过符号链接扩大范围。修改输出目录、项目规则或相关配置后，旧授权可能失效。

达到扫描预算、候选缓存限制或有文件读取失败时，结果会显示不完整及原因。此时只能说“当前已检查范围中找到这些结果”，不能推断其余文件没有相关内容。

## 项目写作规范

在 `.markcaptain/agent.json` 保存语言、读者、语气、术语表与项目搜索偏好，配置版本为 1。推荐通过界面管理；以下是有效结构示例：

```json
{
  "schemaVersion": 1,
  "writing": {
    "language": "zh-CN",
    "audience": "项目使用者",
    "tone": "清楚、简洁",
    "glossary": [
      { "preferred": "MarkCaptain", "avoid": ["Mark Captain"] }
    ]
  },
  "projectSearch": {
    "enabledByDefault": false,
    "include": ["**/*.md"],
    "exclude": ["archive/**"]
  }
}
```

`enabledByDefault` 只影响界面建议，不创建授权。写作规范只有本轮勾选“应用项目写作规范”才随请求使用。配置不保存密钥、认证头或权限，读取缺失配置不会立即创建文件。

保存时会检查外部变更并原子写入，保留未知扩展字段；冲突需重新加载。最终格式化 JSON 上限 128 KiB，不支持的版本或无效配置不应直接用默认值覆盖。

## 本地文档检查

“本地文档检查”由 Rust 检查当前缓冲区，不请求模型，覆盖：

- 标题级别跳级。
- 范围内本地链接和图片目标是否存在。
- 正文是否使用了术语表中应避免的写法。

它不检查外部网址是否可用，不验证标题锚点、跨文档标题内容或语义正确性；代码块和 YAML 不参与术语匹配。绝对路径、越界目标和缺少可验证位置的链接不会被读取。

结果绑定文档身份和正文版本。编辑、切换标签或项目后需要重新检查，旧异步结果不能冒充当前结果。达到预算时显示不完整。

## 模型只读检查与生成修订

“请 Agent 只读检查”会把当前文档快照发给所选模型，要求给出带依据的矛盾、冗余、结构或解释不足等疑点。该模式不启用修改工具、项目授权或联网研究。

检查结果中的“生成待审修订”是另一轮模型请求，会提交该问题及原文证据并生成新审阅卡。用户仍需查看差异并应用，检查结果本身不会修改文档。确定性检查与模型判断解决不同问题，可以结合使用。

## 每次请求启用联网研究

联网研究默认关闭，发送后自动关闭。它不因上一次使用或恢复历史而持续授权。

1. 在本轮启用联网研究，填写研究主题。
2. 如需从当前文档生成候选查询，先勾选“允许根据当前文档形成查询建议”（默认关闭，发送后复位），再点击“从文档建议查询”；候选由文档标题和主题在本地生成，可按需编辑。
3. 逐条批准确切查询词；只有完全匹配获批内容的搜索调用才能发出。
4. 或者明确提供公开文章 URL，让模型按需读取。
5. 核对来源卡的标题、URL、时间和状态，再将证据用于正文。

搜索使用 Bing 公开 RSS 端点，不需要另外提供 Bing API Key。失败后可自行添加公开 URL，但不会把失败查询自动变成网页地址。查询建议本身不会联网，文档正文也不会自动变成搜索词。

直接 URL 只接受无认证信息的 HTTP/HTTPS 常用端口（80/443）和公网地址。每次重定向重新检查，最多 4 次；不用于访问 localhost、内网服务、登录后内容或任意端口。请求不使用系统代理，因此系统代理可访问不代表研究通道也可访问。

可选“本次请求使用 Cloudflare 公共 DNS”默认关闭。开启时 Cloudflare 获得目标域名用于解析，不获得 URL 路径、查询参数或网页正文；不修改系统 DNS，失败不会静默退回系统解析。实际网页请求仍发送给目标站点，检索词发送给搜索服务，模型使用的资料仍发送给所配模型。

来源卡和引用用于保留出处，模型回答仍需人工核对。网页正文仅在当前任务中缓存，历史恢复不会重新开放网络权限。

## 当前预算

| 范围 | 限额 |
| --- | --- |
| 单文档快照、单个项目 Markdown | 2,000,000 UTF-8 字节 |
| 请求中的未保存项目缓冲区 | 128 份，每份 2,000,000 字节，总计 16 MiB |
| 实际读取的项目来源 | 每任务 40 份，每份 2,000,000 字节，总计 16 MiB |
| 项目搜索 | 每任务最多 8 次；最多扫描 5,000 个 Markdown、100,000 个目录项、128 MiB；候选缓存最多 50 |
| glob 规则 | 包含最多 64 条、排除最多 128 条；每条最多 256 字节 |
| 本地文档检查 | 文档 2,000,000 字节；最多 128 个本地目标、200 条问题 |
| Web 研究 | 每任务 8 个批准查询、8 个直接 URL、24 个来源；每次搜索最多 5 个结果 |
| 网页内容 | 单响应最多 1,500,000 字节；缓存正文最多 18,000 字符/来源 |

手动参考和实际项目来源分别计量。减少范围、拆分任务或先保存标签通常比重复请求更有帮助。

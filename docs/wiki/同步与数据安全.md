## 本地保存与远端同步

编辑器、文件树、搜索和资源解析围绕本地工作副本运行。“已保存”表示正文写入本地文件，云端另有等待、同步中、已同步、离线、冲突和错误状态。网络失败不会把一次成功的本地保存变成失败。

一个项目根目录最多有一个活动存储绑定。普通非 Git 目录保持本地模式；打开 Git 仓库根目录会识别分支和首选 remote，可用时建立项目绑定，没有 remote 时不会虚构目标。

单独打开一个文件不会自动加入后台同步。可使用显式单文件上传，选择已配置的非 Git 目标和已有远端目录；上传前先保存本地，同名远端文件产生冲突，不静默覆盖。

## 配置远端连接

进入“偏好设置 → 云存储”，新增连接，选择类型并填写本地根目录。

| 类型 | 配置重点 | 使用范围 |
| --- | --- | --- |
| MarkCaptain Sync | 自建服务地址、workspace ID、访问凭据 | 需要自行部署独立服务 |
| Git | 已有本地仓库、remote、branch | 使用 Git 环境与认证，不是完整 Git 客户端 |
| WebDAV | 服务地址、用户名、密码/Token | 依赖服务的版本与条件写入能力 |
| 存储插件 | 已安装插件、插件配置、必要凭据 | 可信原生程序，通过统一协议扩展其他服务 |

先测试连接，再保存并使用“立即同步”。查看上传/下载数量、Git ahead/behind、冲突和错误。同步目前需要手动触发，没有后台自动重试，也不提供浏览云端历史版本的界面。

连接密码和 Token 进入操作系统凭据库；界面读取连接元数据与是否已保存凭据，不回显秘密。原生存储插件以用户账户权限运行，协议约束不等于操作系统沙箱；只安装可信来源的程序。

## 冲突如何处理

普通文件同步比较上次基线、本地和远端：只有本地变化时条件上传，只有远端变化时更新干净的本地副本，双方变化或删除与编辑相遇时保留冲突，不会用后写入的一方直接覆盖。

WebDAV 使用可用的强 ETag 保护写入；缺少可靠条件写入能力的服务不能等同于安全自动覆盖。出现冲突时先保留本地副本，再核对两端，不把同步按钮当作强制解决冲突。

Git 的普通同步支持 fetch、仅快进 pull 和非 force push，要求仓库状态满足检查，不自动提交或 reset。分叉时可明确发起供审阅的合并，保留未提交结果，或按界面提供的入口中止合并。

Git 冲突可用外部 Git 工具人工解决，也可将有界的 base/local/remote 冲突片段交给现有写作 Agent。Agent 仍只能生成待审建议，不能提交、推送、强推或自动读取整个仓库。完成审阅后仍需按正常 Git 流程确认工作树与提交。

## 恢复机制的区别

| 机制 | 保存/保护什么 | 主要限制 |
| --- | --- | --- |
| 编辑器撤销/重做 | 当前文档的编辑步骤 | 不等于长期版本备份；同文档分屏共享序列 |
| 会话与崩溃草稿 | 恢复打开状态和未保存工作 | 受本机应用数据影响，不能替代独立备份 |
| 独立本地历史 | 有路径 Markdown 的内容快照 | 有保留期限和空间预算，按路径归档 |
| 引用更新事务备份 | 最近重命名/移动时被改写的文件原文 | 不受本地历史清理策略影响，需手动清理 |

Agent 对话历史和多文档修订的原文副本见 [AI 写作助手](https://github.com/yulianjie/MarkCaptain/wiki/AI%E5%86%99%E4%BD%9C%E5%8A%A9%E6%89%8B)。远端版本能力取决于服务，不等于本机历史。

## 独立本地历史的使用

从命令面板打开“本地历史版本”。有路径的文档在打开、保存和定时检查到变化时记录快照；默认检查间隔 60 秒、保留 30 天、总空间 256 MiB，可在窗口中调整。

1. 选择时间版本，查看旧正文、当前正文和差异。
2. 不确定要覆盖时，复制内容或“恢复为新文档”。
3. 选择“恢复当前文档”前，应用必须成功保留恢复前内容。
4. 恢复以编辑事务修改缓冲区，可以撤销；仍需正常保存写盘。

活动文档变化或外部冲突时拒绝恢复。单个快照上限 4 MiB。历史记录失败会提示并允许正常文件保存继续，但恢复当前文档时必须成功保留恢复前快照。

未命名标签在首次保存后才启用独立历史，此前依靠崩溃草稿。历史按路径归档，文件移动后旧版本留在旧路径；当前界面没有浏览已移除路径归档的入口。期限和总空间超限会清理旧版本。

## 配置与数据位置

项目目录中的配置可随项目管理，但不要放凭据：

| 位置 | 内容 |
| --- | --- |
| `.markcaptain/notes.json` | 模板、每日笔记等项目设置 |
| `.markcaptain/agent.json` | 写作规范与搜索偏好，不含访问授权 |
| `.markcaptain/export.json` | 导出预设与项目章节方案 |
| `.markcaptain-sync-manifest.json`、`.markcaptain-sync-journal.json` | 项目根目录下的同步基线与进行中记录，由同步自动维护；使用 Git 时可按需加入 `.gitignore` |
| 文档 YAML/正文 | 别名、标签、属性、任务与链接 |

本机数据分布在应用的系统目录中，具体路径依操作系统而异。以 Windows 为例，“应用配置目录”和“应用数据目录”都是 `%APPDATA%\io.github.yulianjie.markcaptain`，“本地应用数据目录”是 `%LOCALAPPDATA%\io.github.yulianjie.markcaptain`：

| 本机存储 | 用途 |
| --- | --- |
| 应用数据目录 `preferences.json` | 偏好和用户数据 |
| 应用配置目录 `agent-skills.json` | 导入技能副本与启停状态 |
| 应用配置目录 `agent-history/` | Agent 对话历史（启用后） |
| 应用配置目录 `storage-connections.json` | 云存储连接设置（不含秘密） |
| 应用配置目录 `storage-plugins/` | 已安装的存储插件 |
| 本地应用数据目录 `local-history/` | 独立文档本地历史 |
| 本地应用数据目录 `reference-transactions/` | 引用更新事务原文备份 |
| WebView 本地存储 | 轻量区域布局、命名布局等 |
| 操作系统凭据库 | Agent 密钥/认证头、存储连接秘密 |

Agent 历史是本地资料副本，并非加密保险库；导出对话也可能包含正文片段。卸载、迁移或清理应用数据前，应分别备份项目与需要保留的本机记录。备份应用目录不一定能迁移操作系统凭据，换设备后可能需要重新配置。

## 数据何时离开本机

- 普通编辑、索引、独立历史和本地确定性检查不需要发送模型请求。
- 模型使用的消息、实际读取的文档片段、技能和图片会发送到所配模型。
- 联网研究向搜索服务发送获批词，向目标站点请求网页；公共 DNS 选项另有域名披露。
- 同步和图片上传会把相应文件发送到配置目标。
- 外部 MCP 交给持有临时能力凭据的本地客户端，客户端自己的后续使用取决于其配置。
- 检查更新会请求发布清单，安装包只在用户选择下载并安装后获取。

Agent、联网研究和外部 MCP 发送哪些内容，详见 [AI 写作助手](https://github.com/yulianjie/MarkCaptain/wiki/AI%E5%86%99%E4%BD%9C%E5%8A%A9%E6%89%8B)与[项目检索与联网研究](https://github.com/yulianjie/MarkCaptain/wiki/%E9%A1%B9%E7%9B%AE%E6%A3%80%E7%B4%A2%E4%B8%8E%E8%81%94%E7%BD%91%E7%A0%94%E7%A9%B6)。建议用项目副本先验证同步、恢复和迁移，并继续保留独立备份或版本控制。

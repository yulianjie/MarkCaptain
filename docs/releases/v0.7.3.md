# MarkText 0.7.3

补全 v0.7.2 的逐项审阅流程：编辑器撤销与重做会同步审阅反馈，大修改建议也能继续对话。

## 撤销、重做与审阅状态

- 应用建议后，通过编辑器 `Ctrl/Cmd+Z` 撤销，下一轮将对应修改标为已撤回；重做后恢复为已应用。
- 按正文事务检查点关联修改 ID，同批其他项的拒绝决定和审阅原因保持有效。
- 手动编辑后若无法核实原修改是否仍在正文中，显示“当前状态未核实”，并回传 `unverified`，不再声称修改仍已应用。
- 修复 Muya 纯光标历史造成的空撤销，以及从助手面板返回正文时清掉重做分支的问题；键盘和上下文菜单共用内容历史适配。
- 源码和所见即所得模式均保持文档冲突检查，历史恢复不会重新启用旧修改的应用或撤回。

## 大修改与紧凑反馈

- 后续对话使用修改 ID、状态、原因和有限摘录，避免完整 `oldText/newText` 反复追加后超过单条消息限制。
- 超出对话预算时自动缩小反馈摘录；必要时截取较早助手回答并明确标记为摘录，界面显示压缩提示。
- 完整补丁、原因和对话保留本地，用户消息不会被自动裁剪。
- Agent 可通过 `read_review_change` 按 ID 分段读取原文、建议或原因，每次最多 4000 个 Unicode 字符。历史补丁不能作为当前正文直接修改。
- 每轮本地修改资料最多 16 MB、384 项，优先近期修改；超出读取预算的项目明确标记详情不可用，保留原始本地记录。
- 中文、英文、日文提示和使用文档同步更新。

## 验证

- 294 项发布范围内前端单元测试、157 项完整 Rust 测试（含 37 项 Agent 测试）通过。
- 34 项 Agent 浏览器流程测试通过，覆盖两种编辑模式的“应用 → Ctrl+Z → 继续对话”、重做、大补丁继续对话、逐项审阅及历史流程。
- TypeScript、ESLint、生产构建、Rust 格式及差异检查通过。
- 真实回环 HTTP 测试确认完整补丁不会预先发送给模型，仅在工具调用后返回限定片段。
- 本地验证在 Windows 上进行；尚未进行无 Secret Service 的 Linux 桌面实机和真实模型验收。

# A07 多文档修订

日期：2026-10-23。适用于 [v0.8.5](releases/v0.8.5.md) 的多文档修订实现。自动化与 Windows 原生验收状态分别见 [A07 验证记录](A07_VALIDATION.md)，其中实现验收时的应用版本仍为 0.8.4。

## 选择与发送

1. 打开 AI 助手，点击「修订多个文档」。在独立对话框中勾选本次允许修改的文档。
2. 可选择 1–8 个已打开标签，包括已有文件的未保存缓冲区及未命名文档。「打开已有文档…」使用系统选择器和正常编辑器打开流程；打开文件本身不会发送模型请求。
3. 核对文件名、路径和模型服务，填写要求，再点击「发送请求」。每份快照最多 2,000,000 UTF-8 字节，合计最多 4,000,000 字节。
4. 请求开始后冻结所选集合。未勾选的当前文档不会自动成为目标，项目检索范围和只读参考资料也不会扩大可编辑集合。

初始模型请求只包含所选文档的名称、行数、大小、任务内身份及用户要求。正文保留为本地不可变快照，模型通过搜索或读取工具按需获取。对话框可展开查看实际读取的片段、引用和回答。多文档入口默认不携带普通聊天的项目/Web 授权、参考正文或历史对话。

## 按文档审阅

- 每篇文档最多接收一份建议，最多包含 32 处互不重叠的替换。逐文件核对差异后，选择「应用此文档」「忽略此文档」或「撤回已应用修改」。
- 应用和撤回只修改对应编辑器缓冲区，进入该文档正常的编辑器撤销历史。可以在对应文档使用 `Ctrl/Cmd+Z` 和正常重做；一篇文档的操作不撤销另一篇。
- 没有跨文件的「全部应用」或全局撤销事务。某篇发生冲突时，其他仍有效的文档可单独审阅。
- 「转到文档」定位已打开的原标签。「查看原文副本」显示只读的任务起始快照，供核对和人工恢复参考，不自动覆盖当前正文。

源码模式和所见即所得模式共用身份校验、按文件事务及审阅状态同步。分屏中的同一文档仍使用同一缓冲区和正常共享撤销历史。

## 保存与冲突

发送前暂停所选标签的自动保存，清理其定时器并等待已开始的保存/外部变化处理。不会修改全局自动保存偏好；未选择的标签保留原有行为。应用后的内容留在缓冲区，需通过正常手动保存写盘。

已有路径的文档同时保护缓冲区版本与磁盘版本：

| 时机 | 校验 |
| --- | --- |
| 建立任务 | 使用已有文档来源能力读取磁盘；按编辑器编码解码并统一 LF，将内容 SHA-256 与标签的已保存基线比较；已过期的打开缓冲区不能静默开始 |
| 应用/撤回前 | 再读取原始磁盘字节 SHA-256；内容、编码/BOM 或换行字节变化均使旧版本失效 |
| 每个异步边界 | 重查标签对象、标签 ID、路径、正文及当前窗格/模式；关闭后重新打开同一路径不会接续旧任务身份 |

文件删除、改名、外部内容变化或操作等待期间目标变化，会拒绝替换并提示重新发起请求。不会自动刷新、重新定位或重放旧修改。未命名文档没有磁盘探针，仍校验标签与缓冲区身份。

手动保存会改变任务的磁盘基线；如旧建议因此冲突，请重新发起请求。版本检查等待期间新启动的保存也会使旧操作失效。Muya 的正常序列化可能给无末尾换行的原文补一个 LF，撤销与撤回会正确识别这种状态；只读原文副本仍保留原始文本。

磁盘探针只读已由正常打开/保存流程授权的 Markdown 路径，不授予任意文件读取或新写入权限。读取限额同为每份 2 MB、合计 4 MB；缺失、不可读或解码有损返回明确失败。

## 取消与会话边界

「停止」或生成期间关闭对话框会取消当前任务。已经收到并通过校验的建议可保留审阅；迟到事件不能追加旧请求的内容，也不能写入下一次任务。

原文副本、读取记录和多文档审阅只保留在当前应用会话内。发送新请求会替换上一次审阅及其副本，关闭应用后不保留。它们不写入普通 Agent 对话历史，不新增磁盘快照归档，也不提供跨重启回放或恢复承诺。现有普通聊天历史仍按原设置运行。

多文档生成/应用与普通 Agent 生成、分章总结、历史加载及普通建议应用互斥，避免同时使用同一编辑器或后端任务。

## 协议和边界

- 所选身份为 `edit-{UUID}`，每份快照精确绑定 `${requestId}:${documentId}`，偏移为 0。多文档请求的 `context` 为 `null`，不接受 `editRange`，也不允许同时声明只读请求。
- 文档读取、搜索、引用和建议必须指定准确 `documentId`。`current`、未选择身份、项目候选及参考资料不能成为多文档编辑目标。已有参考/项目读取权限始终只读。
- Rust 校验建议后附加权威 `documentId`；输出路由字段不会扩大外部 MCP 建议的输入 schema。旧单文档请求继续使用原工具 schema。
- 单文档工具循环仍最多 10 轮；选择 `n` 篇的多文档任务最多 `10 + 3 × (n − 1)` 轮，上限 31。每轮最多 8 个工具调用，整个任务仍有 300 秒及原响应/上下文限额；选择更多文档不保证模型一定完成所有修改。
- 不新增模型保存、删除、改名、任意创建文件、Git 或 Shell 工具。

生产接口见 [IPC 映射](IPC_MAP.md)，整体设计见 [实施方案 §6.2](LOCAL_DOCUMENT_AGENT_EXPORT_PLAN.md#62-多文档修订)。
